23 skills spec-driven TDD & review deploy to GreenNode auto-triggering

What is it?

A skills package for AI coding agents. “Skills” are reusable instruction sets the agent loads on demand and triggers automatically at the right moment — you mostly just describe what you want. Install once and your agent can:

  • Spec the work, so intent is written down — not lost in a long chat.
  • Build it with planning, test-driven development, and review.
  • Deploy & operate it on GreenNode AgentBase.

It’s a fork of obra/superpowers (MIT) plus an original spec-driven-development skill and GreenNode’s AgentBase skills.

Why it exists

Objective

AI agents drift. Across a long session the “why” lives only in chat history — lost on clear, lost when a new session starts, eroded as context grows. Agents jump to code before the problem is understood, invent tech stacks silently, and produce work no one agreed to review. And once something is built, getting it deployed is a separate scramble.

Spec-Driven Development keeps a persistent spec as the source of truth.
The spec is the brain; the agent is the muscle. You stay the architect and reviewer.
GreenNode AgentBase turns “works on my machine” into a deployed, monitored agent — scaffold, identity, memory, deploy, logs — in a few prompts.

Audience & outcomes

Who is it for, and what can you build?

For: developers, product managers, and teams who use an AI coding agent and want consistent, shippable results — especially anyone deploying agents to GreenNode AgentBase.

Build things like

  • A chatbot / assistant (LangChain or LangGraph) with memory.
  • A RAG or tool-using agent that calls external APIs (managed identity & secrets).
  • An internal automation agent — specced, tested, and deployed to GreenNode.
  • Or any software project — the build + spec half works for non-agent apps too.

Do this with it

Spec a feature → plan it into bite-sized tasks → implement it test-first → review it → scaffold, deploy, and monitor it on GreenNode. All guided, all auto-triggered.

Get it running

Install

Claude Code — try it for one session (no install)

Loads the plugin only for the current session. Great for testing; no conflict with anything installed.

git clone https://github.com/khoapnt-vng/superpowers-plus-greennode-agentbase.git
cd <your-project-folder>
claude --plugin-dir /absolute/path/to/superpowers-plus-greennode-agentbase

Claude Code — install permanently

claude plugin marketplace add khoapnt-vng/superpowers-plus-greennode-agentbase
claude plugin install superpowers-plus-greennode-agentbase@superpowers-plus-greennode-agentbase-dev
# restart Claude Code
Already have the official superpowers plugin? This suite is a superset (it includes all 14 superpowers skills). Disable the official one first to avoid duplicate-skill collisions: 
claude plugin disable superpowers

Other harnesses

The repo ships manifests for Codex (.codex-plugin/), Cursor (.cursor-plugin/), Gemini (gemini-extension.json), and OpenCode (.opencode/). Point each tool’s installer at this repo. Install per harness if you use more than one.

Verify it loaded

Type / and look for superpowers-plus-greennode-agentbase:… entries — or just say “set up a spec for a new agent” and watch a skill trigger.

The workflow

Step by step: build → spec → deploy

Each step is one prompt to your agent; the skill in bold triggers automatically.

  1. Spec it — spec-driven-development

    “I want to build a customer-support agent. Set up the spec.”

    The agent checks for a project constitution (docs/specs/mission.md, tech-stack.md, roadmap.md). None yet? It interviews you (greenfield) or reads your code (legacy), then writes the feature spec: plan.md, requirements.md, validation.md — every acceptance item with a runnable verify: check.

  2. Refine the design — brainstorming

    “Let’s design the agent’s conversation flow.”

    Socratic Q&A, alternatives with trade-offs, a design you approve in chunks.

  3. Plan the work — writing-plans

    “Turn the spec into an implementation plan.”

    Bite-sized tasks (2–5 min each) with exact files, code, and verification steps.

  4. Build it — subagent-driven-development + test-driven-development

    “Execute the plan.”

    Fresh subagent per task, RED-GREEN-REFACTOR, two-stage review (spec compliance, then code quality).

  5. Set up the platform — agentbase-wizard

    “Scaffold this as a GreenNode agent using LangGraph.”

    Scaffolds the project (LangChain/LangGraph templates) and wires memory (agentbase-memory), identity & secrets (agentbase-identity), and LLM access (agentbase-llm).

  6. Deploy it — agentbase-deploy

    “Deploy my agent to GreenNode.”

    Builds & pushes the image to the container registry, creates/updates the runtime, verifies the endpoint.

  7. Operate it — agentbase-monitor / agentbase-teardown

    “Show my agent’s logs.” … “Tear down all resources for this project.”

    Logs, metrics, scaling, and one-shot cleanup when you’re done.

  8. Keep specs in sync (throughout)

    Ask the agent to make code changes so it updates the related spec at the same time — code and spec never drift apart.

Good to know

Tips & FAQ

Do I have to type slash commands?

No. The skills auto-trigger from natural language. Slash commands (/superpowers-plus-greennode-agentbase:agentbase-wizard) are there if you want to be explicit.

Where do my specs go?

Into docs/specs/ in your project — the constitution at the root, each feature in docs/specs/<feature>/.

Can I use it on an existing codebase?

Yes. On a legacy project the agent explores the code and drafts a constitution for you to correct, then continues the normal workflow.

Does it work without GreenNode?

Yes — the spec + build half is general-purpose. The AgentBase skills are what add GreenNode deployment.
